# 목록 검토 절차

SFD는 README 목록을 유지하면서 신규 기여의 근거와 기존 추천의 확인 범위를 검토합니다. 자동 검사는 사람이 검토할 후보를 모으며 자료의 품질·보안이나 추천의 적절성을 판정하지 않습니다. 자동 머지·삭제·추천 해제·거절 댓글은 수행하지 않습니다.

## 신규 기여

1. 기여자가 [기여 가이드](../HOW-TO-CONTRIBUTE.md)와 PR 템플릿에 실제 사용 목적, 공식 근거와 확인일, 이해관계와 최소 확인 결과를 작성합니다.
2. PR 사전 검사는 기준 README와 제출 README를 비교해 새 항목과 설명·라벨 변경 항목을 찾습니다. 문서만 바꾸거나 기존 항목을 그대로 유지하는 PR에는 새 도구의 검증 자료를 요구하지 않습니다.
3. 필수 근거 누락·미확인 상태·설명되지 않은 기본 항목 중복은 보완 대상으로 보고합니다. 추천 재노출과 그대로 유지된 기존 중복은 새 중복으로 취급하지 않습니다.
4. 추적 파라미터·광고성 수식은 경고로만 표시합니다. 이름과 공식 URL이 같은 제품을 가리키는지, 기존 대안 대신 선택할 이유가 충분한지는 관리자가 직접 확인합니다.
5. 관리자는 실제 사용과 문서 확인을 구분하고, 근거가 부족하면 보완을 요청합니다. 소규모 프로젝트, 제작자 기여, AI 사용 자체는 거절 사유가 아닙니다.

`SFD PR preflight` workflow는 기준 커밋의 검사 코드를 실행하고 제출 README와 PR 본문은 데이터로만 읽습니다. 외부 PR 코드를 실행하는 `pull_request_target`이나 쓰기 권한 토큰을 사용하지 않습니다. 사전 검사 성공은 머지 승인이 아니며, 저장소 보호 규칙을 자동 변경하지 않습니다.

PR 본문을 수정하면 `edited` 이벤트로 사전 검사가 다시 실행됩니다. 보고서와 job summary에서 누락 항목과 경고를 확인하고, 여러 리소스를 바꾼 PR은 항목별 근거를 대조합니다.

## 기존 추천

추천의 선택 이유와 제한은 README 설명에 남기고 출처·범위는 [확인 기록](reviews/recommendations.md)에 저장합니다. `recommendations.json`은 검토 증거이며 사이트에 새 항목을 공급하는 목록이 아닙니다. 기존 URL·라벨·식별자는 검토 편의로 바꾸지 않습니다.

- 문서 확인이면 읽은 문서와 확인한 내용을 적고 실행하지 않은 범위를 공개합니다.
- 직접 사용이면 환경·대표 입력·기대 결과·실제 결과를 남깁니다.
- `checked_at`은 실제 검토일이며 링크 검사와 빌드가 자동 갱신하지 않습니다.
- `reviewed_description`은 확인 당시 README 설명입니다. 설명이 바뀌면 이전 기록을 그대로 최신 근거로 사용하지 않습니다.
- 오래되거나 누락된 기록, 바뀐 설명은 재검토 후보입니다. 지원 종료나 가격 변경을 발견하면 공식 근거를 추가하고 사람이 설명·추천 상태를 판단합니다.

## 정기 보고

`Catalogue maintenance audit` workflow는 매주 및 수동 실행으로 보고서와 링크 스냅샷을 남깁니다. GitHub Actions 실행 화면의 artifact에서 보고서를 내려받습니다. 이전 실행의 스냅샷이 복원되면 최종 리디렉션 목적지 변경을 비교하며, 최초 실행이나 캐시 미복원 상태에서는 비교 기준이 없다고 구분합니다.

검사할 내용:

- 링크별 HTTP 상태, DNS·TLS·timeout, 차단·요청 제한과 최종 URL
- 이전 스냅샷과 다른 리디렉션 목적지
- 확인 후 90일 이상 지난 추천, 누락·무효 기록과 설명 변경

HTTP 200은 접속 결과일 뿐 정확성·기능·가격·지원 상태의 검증이 아닙니다. 403·429·TLS 오류·일시 장애는 서비스 종료와 구분하며 자동 삭제하지 않습니다. 가격·지원 종료는 링크 검사만으로 신뢰성 있게 판정할 수 없으므로 공식 공지·가격표를 읽는 재검토의 확인 항목으로 남깁니다.

검사는 공개 HTTP(S) 주소로 제한하며 사설·로컬 주소와 그쪽으로 향하는 리디렉션을 거절합니다. 로그인·API 키·결제·원격 코드를 사용하지 않고 timeout·동시성·리디렉션 수를 제한합니다. 일시적인 외부 링크 장애가 기존 Pages 배포를 중단하지 않도록 배포 workflow와 분리합니다.

## 로컬 검증

저장소 루트에서 실행합니다. 네트워크 없는 회귀 테스트와 실제 외부 링크 검사를 분리합니다.

```sh
python3 scripts/build_site.py
python3 -m unittest discover -s tests -v
python3 scripts/catalog_audit.py --readme README.md --reviews docs/reviews/recommendations.json --output-dir .audit
```

보고서에는 확인하지 못한 상태도 남깁니다. 자동 보고서를 근거 없이 `검증 완료`로 바꾸지 않으며 README·확인 기록 수정 후에는 다시 빌드하고 테스트합니다.

# 추천 확인 기록

추천별 출처와 확인 범위는 [recommendations.json](recommendations.json)에 기록합니다. 사이트 목록은 README에서만 관리하며 이 파일로 목록을 추가하거나 삭제하지 않습니다. 이 기록은 품질 인증이나 전 항목의 가격·라이선스 재검증이 아닙니다.

## 확인 방식

- `document-review`: 공식 문서나 공개 자료를 읽고 해당 범위만 확인했습니다. 로그인, 설치, 코드 생성, API 실행이나 결과의 정확도 시험을 뜻하지 않습니다.
- `hands-on`: 실제 입력·작업과 기대 결과·실제 결과, 실행 환경을 `scope`에 남깁니다. 문서 열람만으로 이 상태를 붙이지 않습니다.
- `checked_at`: 기록에 적힌 범위를 확인한 날짜입니다. 자동 링크 검사나 사이트 빌드로 갱신하지 않습니다.
- `rationale`: 독자가 이 자료를 선택할 상황입니다. 기존 추천을 대체할 필요가 없다면 후보라는 한계를 밝힙니다.
- `limitations`: 직접 확인하지 않은 범위와 사용할 때의 제한입니다.
- `evidence`: 확인한 공식 문서·저장소 URL입니다.

현재 추천 기록은 모두 문서 확인입니다. 문서에서 안내하는 기능과 실제 성능을 구분했으며 계정 접속, 유료 결제, 생성 결과 비교나 설치 시험을 수행했다고 주장하지 않습니다. 추천 설명도 같은 범위로 한정합니다.

## 재검토

추천 확인일이 90일 이상 지났거나 기록이 없으면 정기 보고서의 재검토 후보가 됩니다. README 설명이 달라졌다면 확인일이 최근이어도 기록을 다시 확인해야 합니다. HTTP 200과 리디렉션 정상은 자료의 정확성·보안·지원 지속을 보증하지 않습니다.

확인자가 근거와 범위를 다시 검토한 경우에만 기록을 갱신합니다. 문서가 열리지 않거나 서비스가 차단되면 미확인으로 남기며, 추천 해제·삭제·legacy 표기는 사람이 공식 근거와 함께 결정합니다.

운영 방법은 [목록 검토 절차](../catalog-maintenance.md)를 따릅니다.
